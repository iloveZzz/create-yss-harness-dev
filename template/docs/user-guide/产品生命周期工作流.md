# 通用研发工作流

消费批准 Spec/战略输入，统一组织架构、前后端和测试；不以 Discovery 为默认入口。可继续服务既有通用项目，不要求迁移专职 profile。

`harness-entry → tactical-design → slice-contract → slice-implementation → verification`

1. 检查批准上游与根词汇，形成当前输入、缺口及父 Ticket 汇总。
2. 领域行为命中时准备战术设计；按实际 API/UI/Data 影响准备工程输入。
3. 编译、审查并批准统一 Slice Contract；未受影响分区记录理由，不强迫每个切片修改所有技术层。
4. 在已登记实现仓实施；前端优先 pnpm，后端优先 ./mvnw，独立验证真实用户路径。
5. 汇总合同版本、实际退出码、证据和回滚点；使用专职路线时额外核对跨仓交付基线。

通用研发的就绪政策以本仓 profile 和注册表为准；未选择专职接收路线时不擅自增设前端交付门禁。

本页为阅读导航，不复制定义阶段或批准政策。权威是本仓 docs/process/lifecycle-registry.yaml、docs/process/harness-profile.yaml 与 docs/agents/digital-human-roles.yaml。

完整操作见 [通用研发指南](研发子项目用户手册.md)；输入、输出和命令见 [贯穿案例](设备借用贯穿案例.md)。
