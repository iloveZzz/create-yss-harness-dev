# 维护、升级与兼容指南

## 项目使用者

通用研发提供 attach/sync，具体命令见 [CLI 指南](外部命令行工具实践指南.md)。保存 Git 基线，预览计划，再正常同步；用户修改与冲突人工核对。update/upgrade 只更新 CLI 程序，不更新实例模板。

新流程术语使用 Spec、Ticket、to-spec、to-tickets；历史资产保留可追溯引用，不把重命名当作重新批准。不同家族不能通过覆盖 metadata 迁移。

文档搬迁后先检查索引和本地链接。npm 与 GitHub 状态分别核对，实例模板提交由家族 metadata 记录；最新源码不等于已发布快照。

## 模板维护者

先读根 AGENTS.md 与 docs/process/harness-process-tailoring.md。共享事实改权威资产；修改 Skill 时用 maintaining-skills 并生成投影与锁。日常 scripts/verify-template-fast，候选 scripts/verify-template-candidate，正式分发前完整 scripts/verify-template；命中外部 CLI 时补实际包集成。

提交模板后 CLI 固定完整 SHA、构建并验收，再更新父仓 gitlink。不要循环引用尚不存在的提交，不在模板写真实产品 Spec。源码回滚按已登记 Git 基线与范围执行，用户实例恢复按升级前备份/Git 基线执行。

回到 [通用研发指南](研发子项目用户手册.md)。

本家族实例创建、接管与同步统一使用 `create-yss-harness-dev`；参数见 [CLI 指南](外部命令行工具实践指南.md)。
