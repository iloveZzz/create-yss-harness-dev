# 需求澄清指南

消费批准 Spec/战略输入，统一组织架构、前后端和测试；不以 Discovery 为默认入口。可继续服务既有通用项目，不要求迁移专职 profile。

## 从可观察行为开始

请用户描述谁在什么条件下做什么、成功结果是什么、失败如何恢复。设备借用例子中，应问“审批后是否占用设备”“重复领用怎样返回”，而不是直接选择数据库表结构。

```text
请读取当前批准业务材料，区分已确认决定、待确认问题和可查证的环境事实。
按问题依赖分轮澄清，给出推荐及取舍；先查本地事实，不让我代查。
涉及上游已冻结规则时列出冲突与影响，回交维护方确认后再继续。
```

每轮只问当前能决定的问题；回答不能被解释成超范围的合同/发布批准。业务决定确认后，由所属生命周期更新资产和受影响依赖。本仓不具备战略起草职责时，只整理缺口，不擅自改源 Spec。

输出应包括问题、真实回复、范围、版本、剩余假设与下一步。具体操作见 [通用研发指南](研发子项目用户手册.md)。
